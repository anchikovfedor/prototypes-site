# Tech Context

## Стек

- **React 19** + **TypeScript 5** + **Vite 8**.
- **VKUI 8** (`@vkontakte/vkui` 8.3.0) + `@vkontakte/icons` 3.60.
- **Framer Motion 12** — micro-interactions и **пружины для движения позиции**: `animate()`
  над `MotionValue`, значение пишется в CSS-переменную (прецедент — `apps/mail-scroll`,
  `src/springs.ts`). Форма записи пружин, переносимая в SwiftUI и Compose, и грабли движка —
  в `conventions.md` §«Пружины». Опционально, в конкретном прототипе.
- **react-router-dom 7** — заявлен в `@proto/kit` для будущего url-deep-linking (см. ниже).

## Среда

- Node ставится через **nvm** (Node 24 LTS). Node не в системном PATH — в скриптах/CI
  при необходимости подгружать nvm: `export NVM_DIR="$HOME/.nvm"; . "$NVM_DIR/nvm.sh"`.
- **npm registry с рабочей сети не отдаёт пакеты** (`npm install <новый пакет>` →
  ETIMEDOUT даже с ретраями, при живом `curl` до registry; июль 2026). Установленные deps
  работают. Новые зависимости не добавлять; мелкие утилиты — вендорить однофайловыми
  MIT-реализациями (прецедент: `apps/index/src/vendor/qrcodegen.ts` + `.prettierignore`).
- Самопроверка окружения новичка: **`node scripts/doctor.mjs`** (node/deps/Chrome/gh/шрифты).
- **ffmpeg в системе нет**, а поставить его неоткуда (см. registry выше). Кадры из
  референс-видео тянутся штатным Swift: `AVAssetImageGenerator` + `NSBitmapImageRep` →
  PNG (`swift frames.swift <video> <outdir> <n>`). Тем же способом удобно делать пипетку по
  рендеру и точные кропы — это надёжнее, чем `sips -c`, который на части размеров масштабирует
  вместо кропа. **Пипетка — только `getPixel`, не `colorAt`:** скриншоты с iPhone приходят
  16-битными в Display P3, `colorAt` + `usingColorSpace(.sRGB)` пересчитывает цвет и врёт
  (`#1c85fe` читался как `#1d9bff`), а сырой `getPixel` даёт компоненты в разрядности файла —
  делить на `(1 << bitsPerSample) - 1`. Для сверки с CSS помнить, что sRGB `#1c85fe` в
  P3-скриншоте выглядит как `#4083f5` (проверено 2026-08-05 на `mail-scroll`).
- **JXA (`osascript -l JavaScript`) для AVFoundation не годится** — bridgesupport для неё в
  macOS не поставляется, `$.AVURLAsset` не резолвится даже после `NSBundle.load`.
- **Headless-Chrome по CDP без библиотек:** `--remote-debugging-port` + глобальный `WebSocket`
  Node 24 (puppeteer/playwright в проекте нет и ставить неоткуда). Два приёма, которыми
  ловится анимация (обкатаны на `mail-scroll`, 2026-08-05): **стоп-кадр посреди жеста** —
  `Input.dispatchTouchEvent` `touchStart` + серия `touchMove` **без** `touchEnd`, позиция
  замирает под «пальцем», и состояние можно спокойно замерять; **лаг по кадрам** —
  `Runtime.evaluate` вешает свой `rAF`-цикл, пишущий в массив пары «CSS-переменная позиции ↔
  фактический стиль», потом массив читается одним `evaluate`. Пиксель со скриншота
  (`Page.captureScreenshot` с `clip`) читается тем же Swift, что и кадры видео.
- Windows — только **WSL2** (скиллы завязаны на bash/rsync/BSD-sed/путь к Chrome);
  скрин-сверка на Linux-Chrome — по геометрии, не по глифам (freetype ≠ CoreText).

## Монорепо (npm workspaces)

```
packages/kit   — общий слой: тема VKUI, провайдеры, шеллы под таргеты, dev-переключатель, useStack
apps/_template — шаблон прототипа (копируется под новый; standalone-манифест для домашнего экрана)
apps/index     — лаунчер со списком прототипов (+QR ссылки на прототип по ховеру строки)
apps/<name>    — отдельные прототипы (свой package.json, свой dev-сервер)
(native/     — нативный трек; папка удалена 2026-07-28, см. §«Нативный трек: пауза»)
```

- `@proto/kit` подключается как workspace-пакет с исходниками на TS. В каждом приложении
  `vite.config.ts` содержит `optimizeDeps.exclude: ['@proto/kit']`, чтобы Vite транспилировал
  kit на лету как код проекта.
- CSS подключается сайд-эффектом внутри `packages/kit/src/index.ts`
  (`import './theme/theme.css'`), который `@import`-ит `@vkontakte/vkui/dist/vkui.css`.


## Деплой (публичная ссылка)

Единый статический сайт: `scripts/build-site.mjs` (`npm run build:site`) билдит каждый workspace
`apps/*` с нужным `--base` (index → корень, прототип → `/<name>/`) и склеивает в один `dist/`:
лаунчер в корень, прототипы в подпапки (совпадает с `href` из `prototypes.ts`). База передаётся
**флагом сборки** через env `SITE_BASE` (дефолт `/`); `vite.config` приложений не трогается, dev не
затрагивается. Скрипт пишет `.nojekyll` (нужно для GitHub Pages, чтобы не срезалась папка `_template`).

**Текущее решение хостинга — GitHub Pages через отдельный ПУБЛИЧНЫЙ site-репо** (реализовано в
`.github/workflows/deploy.yml`, закоммичено, **сайт live** —
`https://anchikovfedor.github.io/prototypes-site/`; ход миграции в progress.md → «Миграция … ВЫПОЛНЕНО»).
Ветка `main` того же публичного репо — **зеркало каркаса для дизайнеров** (kit, публичные
прототипы, скиллы, memory-bank; обновляется вручную `scripts/export-public.mjs`), `gh-pages` —
только билд сайта.

- **Что попадает в зеркало — только список `PUBLIC_APPS`**, новые прототипы туда сами не
  добавляются. `mail-scroll` / `mail-scroll-v2` в него **не входят** (решение пользователя
  2026-08-10: разработке уходят ссылки на Pages и `HANDOFF.md`, исходники — нет; в `src/assets`
  лежат фотографии аватарок).
- **Санитайзер `sanitizeDoc()`** чистит внутренние идентификаторы (ключи Figma-файлов, номера
  задач) в `HANDOFF.md`, `NOTES.md` и **`memory-bank/`** — последнее добавлено 2026-08-10:
  memory-bank копируется в зеркало всегда, и `<internal-ticket>` из него уезжал в публичный репо.
  Новый прототип = новый ключ и тикет: при добавлении в `PUBLIC_APPS` дописывать замены и
  проверять `node scripts/export-public.mjs build <tmp>` + грепом, прежде чем `publish`.

- **Причина выбора:** критерий — бесплатно, доступно всей команде, исходники остаются в
  приватном репо. Vercel и Cloudflare Pages не подошли (доступность для команды + ограничения
  бесплатных планов), см. «Отвергнутые варианты» ниже.
- **Модель (Model B, «build-then-publish»):** исходники в приватном `anchikovfedor/prototypes`;
  GitHub Actions на push в `main` → `npm run build:site` c `SITE_BASE=/prototypes-site/`
  → `peaceiris/actions-gh-pages@v4` пушит **только** `dist/` в ветку `gh-pages` публичного
  `anchikovfedor/prototypes-site`; на нём включён Pages. Публичен лишь билд (тот же клиентский код,
  что и так отдаётся браузеру); sourcemaps у Vite по умолчанию **off** → TS-исходники не утекают.
- **URL:** `https://anchikovfedor.github.io/prototypes-site/`.
- **Доступ:** SSH deploy key — приватный ключ в secret `ACTIONS_DEPLOY_KEY` (приватный репо),
  публичный — deploy key с write в `prototypes-site`. Настройка репо/ключа/secret/Pages делалась
  через **`gh` CLI** (scope `repo`).
- **Первый деплой — медленный (важно):** первый в жизни деплой нового Pages-репо провижинит
  CDN/DNS и может идти **до ~15–20 мин** (внутренний job `deploy` висит `in_progress`, хотя
  Actions-сборка и Pages-`build` зелёные, а контент уже в `gh-pages`). **НЕ отменять прогон** —
  cancel сбрасывает провижининг и удлиняет ожидание. Обычные Pages-`build` этого репо — 7–14 мин.
- **Legacy Pages-`build` бывает нестабилен:** билд может упасть с generic «Page build failed.»
  или зависнуть в `building` на десятки минут — контент обычно ни при чём. Лечение — **не ждать
  смерти зависшего билда**: `gh api -X POST repos/anchikovfedor/prototypes-site/pages/builds`
  **вытесняет его** (старый сразу `errored`, новый стартует). Если зависания станут
  регулярными — план Б: перевести Pages на `build_type=workflow`
  (`actions/upload-pages-artifact` + `actions/deploy-pages`); workflow-файл придётся класть
  в `dist/` через `build-site.mjs`, т.к. пуш идёт в `gh-pages`.
- **Пуш без изменений `dist/` не деплоится — это норма:** peaceiris при неизменном контенте не
  создаёт коммит в `gh-pages` («nothing to commit», прогон зелёный) → Pages-`build` не
  запускается, live остаётся прежним. Не путать с пропавшим деплоем.
- **Проверять деплой по контенту, не только по «success».** После пуша Actions-job зеленеет
  быстро, но **CDN Pages ещё несколько минут отдаёт прошлый hashed-бандл** (публичный URL — старый
  `index-*.js`), пока Pages-`build` не станет `built`. Сверять: HEAD ветки `gh-pages` = наш коммит
  (`gh api …/commits/gh-pages`) **и** сменился ли hash JS на публичном URL — а не только `gh run`.
- **Важно про base:** абсолютные литералы к public-ассетам в JS (`'/photos/x.png'`) Vite при
  подпапочном `base` **не переписывает** (в отличие от HTML и CSS `url()`) — на подпапке они 404-ят.
  Для таких ссылок использовать `import.meta.env.BASE_URL`. Именно из-за этого в `documents-css`
  фото были убраны (см. progress.md).
- **Новый прототип со шрифтами — дописать в `deploy.yml` руками.** Список приложений в шаге
  «Restore proprietary fonts» захардкожен (`for app in cards-drum documents-css mail-scroll
  mail-scroll-v2`). Грабли на каждый прототип, который подключает VK Sans.
  **Забыть не значит увидеть красный прогон:** сборка проходит **зелёной**, Vite лишь пишет в
  лог `./fonts/VKSansDisplay-Regular.ttf … didn't resolve at build time`, а на проде шрифт
  отдаёт 404 и заголовки едут системным. Так и случилось с `mail-scroll-v2` при первом
  деплое (починено в `b6d7b12`). Проверять: `gh run view <id> --log | grep "didn't resolve"`
  либо `curl -o /dev/null -w '%{http_code}' <прод>/assets/VKSansDisplay-Regular-*.ttf`.

## Навигация и переходы

- Переходы между экранами — **встроенные в VKUI**, на CSS:
  - `View` (`activePanel` + `history`) — push/back между панелями;
  - `Root` (`activeView`) — переключение стеков View;
  - `Epic` (`activeStory` + `tabbar`) — табы;
  - `ModalRoot` + `ModalPage`/`ModalCard` — модалки и шторки;
  - `SplitLayout` + `SplitCol` — многоколоночный большой экран.
- `kit.useStack(initial)` — стек экранов (history + push/back/reset) для `View`.
  Даёт корректные push/back переходы из коробки, без URL.
- Тумблер анимаций: `ConfigProvider.transitionMotionEnabled` (управляется dev-панелью и
  стартует от `prefers-reduced-motion`).

### Планируемое улучшение: url-deep-linking
`react-router-dom` уже в зависимостях `kit`. Когда понадобится адресация конкретного
экрана по URL и браузерная «назад» внутри прототипа — добавить в `kit` обёртку
`useRoutedStack` (синхронизация стека с `useLocation`/`useNavigationType`). Пока не
реализовано осознанно (Simplicity First): на уровне прототипа URL уже уникален.

## Стратегия анимаций: CSS (VKUI) vs Framer Motion

- **По умолчанию — VKUI/CSS.** Все переходы между экранами уже анимированы VKUI; это и есть
  то, что переносится в продакшн без переписывания.
- **Framer Motion — точечно**, для micro-interactions, которых нет в VKUI (пружины, жесты,
  layout-анимации). Пример: `apps/reference/src/components/LikeButton.tsx`.
- Framer-анимации обязаны уважать `prefers-reduced-motion` (`useReducedMotion`) и тумблер
  Motion из `usePrototypeSettings()`.
- **Ведение за пальцем и доводку держим на CSS-переходах, а не на FM** (решение по
  `mail-scroll`, 2026-07-31): CSS-переход идёт вне main thread и корректно прерывается,
  а FM-шорткаты (`x`/`y`/`scale`) считаются на главном потоке — рядом с `filter: blur` это
  ровно тот запас, которого может не хватить на iOS. Позицию во время жеста ведём инлайн-
  стилем императивно; на коммите снимаем инлайн и переключаем класс **в одном пересчёте
  стилей**, тогда переход доигрывает остаток от текущей точки.
- **Целевую позицию класса замеряем только с погашенным переходом** (`mail-scroll`,
  2026-08-03): `getComputedStyle(el).transform` у элемента с `transition` отдаёт значение
  идущего перехода, а не цель класса (Blink — даже в покое, сразу после навешивания класса),
  а при инлайн-трансформе — его. Порядок: навесить класс с `transition: none`, снять инлайн,
  прочитать, вернуть всё и **прочитать ещё раз под тем же классом** (иначе замер станет
  точкой отсчёта нового перехода и элемент прыгнет), затем убрать `transition: none`.
- **Значение, которое нужно и в CSS-переходе, и в кадре жеста, держим в CSS-переменной**
  (`--mail-exp-blur`): инлайн пишем как `blur(calc(var(--…) * ${p}))`, и тогда отключение
  эффекта в reduced-motion делается занулением переменной — в одном месте, без ветвлений в JS.

## Жесты (touch/pointer)

- **VKUI `Touch`** (`@vkontakte/vkui`) — жестовый примитив дизайн-системы (им VKUI делает свой
  swipeBack). `onStart`/`onMoveX`/`onEnd` дают `startX`/`shiftX`/`shiftXAbs`/`duration`; работает и
  мышью, и тачем. Предпочтителен перед Framer Motion, когда жест нужен «в вебвью» без новых
  зависимостей. Пример — edge-swipe закрытия в `documents-css` (см. progress.md).
  - **Грабли:** `gesture.shiftX`/`clientX` пишутся **только пока навешен** `onMoveX`/`onMove`
    (гейт по `isSlide`, `Touch.js:109,117`). Читаешь сдвиг в `onEnd` — всё равно нужен `onMove*`
    (пусть **пустой**), иначе там `0`.
  - **Одна точка** — мультитача/`scale` нет. Для **pinch** не годится (нужны сырые touch-события /
    WebKit `gesturechange` / `wheel`+`ctrlKey`).
- **Pinch в мобильном Safari зарезервирован** (pinch-in → зум-аут → обзор вкладок) и надёжно из
  страницы **не отключается** (iOS игнорит `user-scalable=no`/`maximum-scale`; `gesturestart`+
  `preventDefault` хрупкий; обзор вкладок — на уровне хрома). Кастомный pinch работает в **WKWebView**
  (нет вкладок Safari, хост гасит зум) и на десктоп-**трекпаде** — но не в браузерном Safari.
- **Резинка (overscroll) браузера гасится `touch-action`, а не `overscroll-behavior`.**
  `overscroll-behavior: none` работает только с Safari 16+; надёжнее забрать жест до
  скролл-машины браузера: `touch-action: none` на зоне жеста, когда скроллить нечего, и
  `pan-y` — когда внутри есть настоящий скроллер. `overscroll-behavior: none` на `html/body`
  ставим вторым слоем (он же снимает pull-to-refresh на Android). Проверено на `mail-scroll`.
- **`overscroll-behavior: contain` не гасит собственный отскок** элемента — только проброс
  наружу. Для скроллящегося блока внутри кастомной шторки нужен `none`, иначе отскок у его
  границы конкурирует с жестом закрытия.
- **Хаптик:** полный обзор вариантов, библиотек и обходных путей — `research-haptics-web.md`
  (ресёрч 2026-08-03). Кратко: `navigator.vibrate()` есть в Android Chrome; **в iOS Safari Web
  Vibration API не реализован** и в Interop 2026 не заявлен. Вызывать под guard
  (`typeof navigator.vibrate === 'function'`).

  На Android вызов гейтится **user activation** (до первого касания фрейма `vibrate()` вернёт
  `false`), видимостью документа и системными настройками вибрации. Длительность **меньше ~20 мс
  ненадёжна** — мотор не успевает раскачаться; ориентир по библиотекам: `light` 15–35 мс.
  Управления амплитудой в вебе нет вовсе.

  Обходной путь на iPhone один — **нативный switch-контрол** (iOS 17.4+, хаптик с iOS 18.0):
  `<input type="checkbox">` с `setAttribute('switch','')`, невидимый (`opacity: 0`; у
  `display/visibility: hidden` клик не проходит), система сама даёт тап при переключении.
  Приём с `mishanaer.com`. **Проверено стендом на устройстве (2026-07-31, `mail-scroll`):
  срабатывает только реальное касание контрола по его собственной оси** — тап по видимому
  switch, тап по невидимому switch под кнопкой (`pointer-events: auto` на `pointer: coarse`),
  перетаскивание вдоль его оси. Не работает: программный `click()`, смена `checked` без клика,
  вертикальный свайп по контролу, повёрнутому на 90°.

  Перепроверено стендами 2026-08-03 на iOS 26.5+: программная форма у библиотек — клик по
  связанному **`<label>`** (в стенде 31.07 проверялся `input`), но **и она мертва**. Перебраны
  16 комбинаций «форма контрола × момент вызова» (видимый / `opacity: 0` нормального размера /
  накрытый / `1×1` / за экраном / `pointer-events: none`; `click`, `touchstart`, `touchmove`,
  `touchend`, `setTimeout`, `rAF`, `transitionend`) — хаптика нет нигде. Причина в коммите
  WebKit (bug 285120): «It should not be possible to generate haptic feedback from script alone».
  **Живёт только переключение контрола пальцем.**

  Практический вывод: **тапу хаптик дать можно, свайпу и любому асинхронному моменту — нет.**
  В нативе ограничения нет (`UIImpactFeedbackGenerator`), внутри VK/Telegram — есть мост хоста
  (`VKWebAppTapticImpactOccurred`). И грабля: такой контрол нельзя держать внутри зоны жеста —
  клик по нему всплывает в её `onClick` и коммитит состояние посреди свайпа.
- **Тап и драг на одном элементе:** отличать по `shiftYAbs > 5` (порог VKUI `slideThreshold`),
  после драга клик игнорировать. `touchEnd` сам порождает `click` — отдельный обработчик
  мыши не нужен.

## Нативное меню ОС в вебе — только `<select>` (2026-08-04, `mail-scroll`)

Настоящее нативное меню (`UIMenu`/`UIContextMenu`, системное меню Android) веб-странице
**недоступно — API нет**. Единственный элемент, который рисует сама ОС, — `<select>`: на iOS
это системный **пикер-колесо снизу**, на Android — диалог со списком. Вид, подписи кнопок и
анимация не настраиваются вовсе. Нужен именно **вид меню** — брать компонент дизайн-системы
(VKUI `ActionSheet`, `mode: 'sheet' | 'menu'`), но это HTML, а не ОС.

- **Открыть пикер программно нельзя надёжно:** `HTMLSelectElement.showPicker()` поддержан не
  везде и требует user gesture. Значит тап обязан прийти **в сам `<select>`** — прозрачный
  (`opacity: 0`) слой поверх «кнопки», тем же приёмом, что нативный switch-контрол выше.
- **Плата:** зона под слоем выпадает из жестовой сцены — жест, начатый ровно с неё, уходит в
  контрол, а не в свайп/pull-to-refresh. Слой надо гасить (`display: none`) в состояниях, где
  кнопки не видно, иначе он ловит тапы вслепую.
- **Грабля: `opacity: 0` не гасит подсветку нажатия.** WebKit рисует
  `-webkit-tap-highlight-color` отдельным оверлеем поверх бокса элемента, **независимо от его
  прозрачности**; на устройстве это выглядело как белый прямоугольник вместо кнопки — по форме
  бокс контрола (radius 0), а не кнопки под ним (radius 16). Лечится
  `-webkit-tap-highlight-color: transparent`; свои кликабельные VKUI глушит тем же правилом, а
  самописный контрол — нет. **Статус: диагноз, на устройстве не подтверждён** — headless
  подсветку нажатия не рисует вовсе, воспроизвести и проверить лечение локально нельзя.

## Progressive blur (градиентное размытие) — в CSS не собирается

Проверено замерами на `mail-scroll` (полоска блюра 12 → 0 из макета <internal-ticket>):

- у CSS **нет** `backdrop-filter` с переменным по высоте радиусом; имитация — только лесенкой
  слоёв, а ступеньки **дают видимые горизонтальные полосы** (дизайнер забраковал);
- слои обязаны быть **соседями**: элемент с `backdrop-filter` создаёт backdrop root, и его
  потомкам размывать уже нечего (замер: отключение фильтра на вложенных `::before`/`::after`
  меняло картинку на **0.000** — слои не работали вовсе);
- область фильтра задаётся **высотой элемента, а не маской**: Chrome не обрезает
  `backdrop-filter` маской (с маской на верхнюю четверть резкость внизу плашки 0.76, с
  ограничением по высоте — 17.5).

Итог: в вебе оставляем **градиент в белый** вместо блюра. Настоящий progressive blur — только
натив (`UIVisualEffectView` + маска) или шейдер на canvas/WebGL.

## Нативный трек (iOS/Android)

Верифицировано (2026-07-13): **VKUI — веб-библиотека (DOM)**, официальная поддержка —
браузеры и **webview iOS/Android**; React Native-версии нет. «VKUI в нативных приложениях» =
webview-поверхности → для них веб-прототипы **уже на продакшн-стеке**. Чисто нативные экраны
(Swift/Kotlin) — передаётся референс + спека значений, не код. Уровни (критерий выбора —
куда пойдёт фича в проде):

- **L0 — device-true веб (в дереве, работает):** QR в лаунчере (ховер строки) +
  standalone-манифест в `_template` (прототип с домашнего экрана без хрома браузера).
  Иконки заполнены (2026-07-28): `icon-192/512.png` (`purpose: any`, скругление зашито в
  картинку — Android рисует такую иконку как есть), `icon-maskable-512.png` (`maskable`,
  глиф в центральных ~80%), `apple-touch-icon.png` 180×180 (непрозрачный квадрат, iOS
  скругляет сам). **На Android иконки 192+512 обязательны:** без них Chrome не собирает
  WebAPK и деградирует до ярлыка, открывающегося в Custom Tab с адресной строкой (на iOS
  этого различия нет). **Фон под статус-баром** (макет с цветной шапкой) требует
  `apple-mobile-web-app-status-bar-style: black-translucent`: при `default` вебвью в
  standalone начинается ниже статус-бара и `env(safe-area-inset-top)` = 0. Плюс `theme-color`
  в HTML и `theme_color`/`background_color` в манифесте. **iOS запоминает эти значения в
  момент установки** — после правки старую иконку с домашнего экрана надо удалить и добавить
  заново, иначе выглядит как «деплой не доехал» (в Safari изменения видны сразу). Графика — плейсхолдер «P» на `#0070f0`, под конкретный прототип
  заменяется целиком; сгенерирована headless-Chrome'ом из HTML (рендер 512 + `sips -z`;
  при `--window-size` < ~500 Chrome считает `vw` от большего вьюпорта и кадрирует).
  **Важно (сверено на проде 2026-08-03):** манифест есть только у `_template` и `mail-scroll`;
  у `documents-css`, `cards-drum`, `reference` и **у самого лаунчера** его нет — они ставятся
  ярлыком без standalone. Разбор и что с этим делать — ниже, §«Как прототип попадает на чужое
  устройство».
- **L1 — shell (был `native/shell`, из дерева удалён 2026-07-28):** Capacitor (реальный
  WKWebView/WebView, как продакшн-встройка; pinch работает — в Safari он зарезервирован),
  грузил **live-URL**, так что новые прототипы приезжали веб-деплоем без пересборки.
  Каркас на устройстве так и не верифицирован. Код и README — в истории git, коммит
  `66e064c`; вернуть: `git checkout 66e064c -- native/shell` (плюс правила `native/shell/ios|android`
  в `.gitignore`, они убраны вместе с папкой).
- **L2 — настоящий нативный UI (пилот начат и свёрнут 2026-07-28):** решено делать
  **SwiftUI + Compose** двумя отдельными кодовыми базами (не Expo/RN и не Compose
  Multiplatform); Expo отпал в т.ч. из-за недоступного с рабочей сети npm registry.
  Подробности и состояние — ниже, §«Нативный трек: пауза».

### Как прототип попадает на чужое устройство: сравнение маршрутов (2026-08-03)

Собрано по вопросу «пусть прототип открывается сразу как отдельное приложение, а не ссылкой
в браузере; в iOS вроде есть миниаппы, открывающиеся по QR». Решение по маршруту **не принято** —
это документ для выбора.

**Вердикт по автозапуску (подтверждает и расширяет запись progress.md от 2026-07-30).**
Ссылки, которая сама откроет прототип в standalone, не существует ни на одной платформе.
Эффект «открылось как приложение» достигается ровно двумя путями: получатель **один раз ставит
иконку** (PWA) либо на устройстве **уже стоит контейнер** (своя оболочка или приложение VK).
Две ветки закрыты окончательно:

- **iOS App Clips** («миниаппы по QR» из вопроса) — запускаются App Clip Code / QR / NFC /
  Safari-баннером, но требуют Apple Developer Program ($99/год, отложен решением 2026-07-12),
  **родительское приложение, опубликованное в App Store**, и нативный код (webview-обёртка —
  риск отказа на ревью). Тест без App Store — TestFlight (та же платная программа) или
  Local Experiences, которые настраиваются вручную в Settings **на каждом устройстве**.
- **Android Instant Apps** (аналог) — **выключены Google в декабре 2025**: публикация через
  Play и Instant-API отключены, тулинг убран из Android Studio. Замены нет.

**Матрица маршрутов.** Целевое ограничение — **чужие устройства, iOS и Android одновременно**.

| Маршрут | Шаги получателя | iOS (чужое устр.) | Android (чужое устр.) | Что видит | Цена / блокеры |
| --- | --- | --- | --- | --- | --- |
| **PWA прототипа** | ссылка → меню браузера → «На экран Домой» → тап по иконке | ✅ | ✅ (WebAPK) | иконка, standalone, без адресной строки | 0 ₽; шаги различаются в каждом браузере |
| **PWA лаунчера (общий scope)** | то же **один раз**, дальше все прототипы изнутри | ⚠️ проверить | ⚠️ проверить | одна иконка «Прототипы», переходы в подпапки остаются в standalone | 0 ₽; манифеста у лаунчера сейчас нет |
| **Оболочка Capacitor** | поставить APK / получить билд | ❌ без TestFlight | ✅ (sideload APK) | настоящее приложение, реальный WKWebView/WebView | iOS — $99/год; на устройстве не верифицирована |
| **VK Mini App** | ссылка `vk.com/app{ID}` или QR → открывается внутри VK | ✅ | ✅ | внутри VK, хром VK сверху; ровно продакшн-webview VKUI | 0 ₽; каждого зрителя надо добавить в админы/тестовую группу |
| **App Clip** | скан App Clip Code | ❌ | — | — | $99/год + приложение в App Store |

**Состояние в репозитории (сверено с прод-сайтом `curl`, 2026-08-03).**

- Устанавливаемые PWA на live — **только `_template` и `mail-scroll`** (манифест и все четыре
  иконки отдают 200). У `documents-css`, `cards-drum`, `reference` — **404 на всё**: на домашний
  экран они лягут ярлыком без standalone, на Android — без WebAPK.
- **У лаунчера (`apps/index/index.html`) манифеста нет вовсе** — вариант «одна установка на все
  прототипы» сейчас физически недоступен, хотя стоит дешевле остальных: манифест в корне сайта
  даёт scope `/prototypes-site/`, то есть переходы в подпапки прототипов остаются внутри
  установленного окна. **Поведение in-scope навигации надо проверить на живых iOS и Android** —
  из окружения не проверяется.
- QR в лаунчере (`apps/index/src/QrBadge.tsx`) появляется **по ховеру строки** — это сценарий
  «навести камеру на свой экран», а не «отправить коллеге»; для раздачи он не работает.
- **Долг (подтверждён):** `short_name` у `mail-scroll` = `"Prototype"`, а все четыре PNG
  **побайтово совпадают** с `_template` (`cmp`) — установленные иконки неотличимы между собой.

**Детали по живым маршрутам.**

- *PWA + install-подсказка.* Пошаговая матрица браузеров (детект, шаги, результат, две дыры
  детекта — встроенные браузеры iOS и Mac-UA у iPadOS) уже разобрана в progress.md §«PWA:
  автозапуска по ссылке нет» — здесь не дублируется. Там же намечена реализация плашки
  (`detectInstallTarget.ts` + `instructions.ts` + `InstallHint.tsx`) и решение **не добавлять
  service worker** (риск закешированной старой сборки > выигрыша). Осталось: сама плашка,
  манифесты трём прототипам, погашение долга иконок.
- *Оболочка Capacitor.* Код в истории: `git checkout 66e064c -- native/shell`. Грузит live-URL,
  новые прототипы приезжают обычным веб-деплоем без пересборки. **Для заявленной цели закрывает
  только Android** (APK файлом); на чужой iPhone без TestFlight не ставится. На устройстве ни
  разу не верифицирована (см. L1 выше).
- *VK Mini App.* **Проверено по документации 2026-08-03** — фетчится `dev.vk.ru`
  (`dev.vk.com` из рабочего окружения недоступен, это важно для следующего захода):
  - Мини-приложение = обычное **SPA на HTML/JS/CSS**, встраивается **WebView** на мобильных и
    **iframe** на десктопе. Наш стек подходит без переписывания.
  - Регистрируется на портале разработчиков, тип «Мини-приложение». В разделе **Размещение** —
    URL приложения, **HTTPS обязателен** (GitHub Pages подходит) + **режим разработки** с
    отдельным URL: админы приложения открывают тестовый адрес, остальные — прод.
  - **Модерация не нужна для показа своим:** до неё «мини-приложение отключено для пользователей
    и видно только его создателю» по `vk.com/app{ID}`; доступ выдаётся **добавлением
    администраторов или тестовых групп**. Каталог и модерация нужны только ради трафика.
  - Открывается прямой ссылкой `vk.com/app{ID}`; платформа дописывает параметры запуска в URL
    (пользователь, язык, платформа, `vk_ref`) и подписывает их — нам подпись не нужна,
    прототипы без бэкенда.
  - **`VKWebAppInit` вызывать обязательно** — этим приложение сообщает платформе о запуске.
    Библиотека VK Bridge ставится из npm, **а registry с рабочей сети недоступен** → потребуется
    либо вендорить браузерную сборку файлом (прецедент — `apps/index/src/vendor/qrcodegen.ts`),
    либо обойтись сырым `postMessage` протокола Bridge. Какой путь сработает — **проверяется
    первым же запуском**, заранее не утверждать.

  Цена сценария: **каждого зрителя надо добавить в админы или тестовую группу приложения** —
  это не «отправил ссылку и всё». Плюс один `app_id` = один URL, поэтому пятью приложениями
  под пять прототипов заводиться не стоит: указывать URL **лаунчера**, а прототипы открывать
  навигацией внутри.

**Открытые вопросы (нужны для выбора маршрута).**

1. Допускает ли внутренняя политика заводить приложение на платформе VK под внутренние
   прототипы — пусть и в режиме «видно только админам и тестовой группе».
2. Откроет ли **системная камера** (не сканер внутри VK) ссылку `vk.com/app{ID}` сразу в
   приложении VK, а не в браузере — по докам не проверяется, решается одним сканом на устройстве.
3. Остаётся ли Apple Developer Program отложенным: он разблокирует и TestFlight-оболочку на
   чужие iPhone, и App Clips.
4. Сколько людей и как часто получают прототипы — от этого зависит, окупается ли разовая
   установка контейнера (или заведение в тестовую группу VK) против подсказки на каждой ссылке.

**Рекомендация при текущих ограничениях (чужие устройства, iOS + Android, без трат).**
Маршруты не конкурируют — оба стоят дёшево и опираются на один и тот же live-сайт:

1. **PWA, начиная с манифеста лаунчера** — одна установка покрывает все прототипы, включая
   будущие, без правок в каждом приложении. Работает для кого угодно, без списков доступа.
2. **VK Mini App поверх того же лаунчера** — даёт буквально запрошенный сценарий (скан → открылось
   приложением) и ровно продакшн-webview VKUI, ценой добавления зрителей в тестовую группу.

Оболочка Capacitor остаётся третьей опцией с лучшим feel, но закрывает только Android.

**Выбор web vs native для конкретной фичи (и роль IDE)** (зафиксировано 2026-07-28):
- Критерий — **что доказываем**. Дизайн взаимодействия / хореография / состояния / визуал
  PTR → **веб** (дешевле, весь цикл в VS Code + Vite; для нативной цели выхлоп = референс +
  спека, не переносимый код). Точная **физика** скролла (инерция, оверскролл, rubber-band,
  fling, PTR-хаптик) → **натив**: системные компоненты (Compose `PullToRefreshBox`+`LazyColumn`,
  SwiftUI `List{}.refreshable`) дают верный feel «бесплатно»; веб её только приближает
  (Chromium-скролл + `overscroll-behavior`, а VKUI `PullToRefresh` — JS/DOM, не системный
  `SwipeRefreshLayout`). Collapsing/parallax-заголовок — паритет (умеренная работа на обоих).
- **IDE:** веб-путь целиком в VS Code (проверка на устройстве — QR/PWA или L1-оболочка).
  Настоящий нативный экран (SwiftUI/Compose) — Xcode/Android Studio (preview, Gradle, подпись);
  VS Code для Compose непрактичен.
- **Важно:** открыть `native/shell` в Xcode/Android Studio ≠ нативный UI — это тот же
  веб-прототип в WebView. Нативный прототип = **отдельная кодовая база** (VKUI в SwiftUI/Compose
  не конвертируется); может лежать папкой в этом репо, но общего с веб-кодом не имеет.
- **Передача натива:** Android — debug-APK (отправить файл, sideload). iOS на **чужие**
  устройства — только TestFlight → Apple Developer Program ($99/год, отложен); иначе кабель +
  Xcode на своё устройство или симулятор (Mac). Для оценки feel часто достаточно видео 1×/0.25×.

  Поэтому пилот дошёл до симулятора, но не до устройства (iPhone 15 Pro подключён и доверен).
- **Android-тулинга нет вообще**: ни Android Studio, ни SDK, ни `adb`, ни JDK (`/usr/bin/java` —
  заглушка). Также нет `brew`, `ffmpeg`, `xcodegen`. Диск: после загрузки платформы ~26 ГБ свободно.
- Google Maven / Maven Central / services.gradle.org / npm registry с домашней сети отвечают 200;
  ограничение «registry недоступен» — свойство **рабочей** сети.
- **Xcode-проект генерируется без GUI:** `project.pbxproj` с `objectVersion = 77` +
  `PBXFileSystemSynchronizedRootGroup` (папка исходников как synchronized group) — новые `.swift`
  подхватываются без правки pbxproj; shared-схема кладётся в `xcshareddata/xcschemes/`. Проверено:
  `xcodebuild -list` видит target/схему, сборка под симулятор проходит, приложение запускается
  (`simctl install/launch`, скриншот через `simctl io booted screenshot`). Тайпчек без платформы —
  `swiftc -typecheck -swift-version 6 -sdk "$(xcrun --show-sdk-path --sdk macosx)"`.
- Пилотный экран (удалён вместе с папкой, восстанавливается за минуты): `NavigationStack` +
  `List` на 30 элементах + `.refreshable` + `.sensoryFeedback(.success, trigger:)`; системный
  PTR своего хаптика не даёт. Кастомных значений motion нет намеренно — источник `system default`.

## Кросс-агентность (Codex)

- Точка входа — **`AGENTS.md`** (корень): скиллы `.claude/skills/*` = канонические
  процедуры для любого агента; там же конфиг Figma MCP для Codex (`~/.codex/config.toml`
  → `https://mcp.figma.com/mcp`).
- **Гейт перед первой анимацией в Codex:** живой тест `get_motion_context` — Figma Motion
  (open beta) официально отдаёт motion-контекст любому MCP-клиенту, но в публичном
  tools-списке сервера инструмент пока не значится. Недоступен → «Codex = только статика»,
  анимация из Claude Code или по таблице-спеке в HANDOFF.

## Зафиксированные решения (почему так)

- **Хаптик на iOS в вебе не делаем** (2026-08-03): программный путь закрыт Apple в iOS 26.5,
  остаётся только переключение нативного switch пальцем — то есть контрол в зоне жеста ради
  одного сценария из трёх. Мост VK Mini App (`VKWebAppTapticImpactOccurred`) даёт все три
  момента, но **отложен** вместе с маршрутом «VK Mini App поверх лаунчера». На Android хаптик
  остаётся, лечится длительность (см. progress.md §«Хаптик в вебе», обзор —
  `research-haptics-web.md`).
- **VKUI 8 + react-router-dom**, а не `@vkontakte/vk-mini-apps-router`: VK-роутер (последний
  1.8.4) поддерживает только VKUI ≤7 и тянет `vk-bridge`. Остаёмся на последнем VKUI 8; для
  URL-навигации, когда понадобится, берём нейтральный react-router (он же ближе команде при
  передаче). Не пытаться «вернуть правильный VK-роутер».
- **Монорепо с независимыми приложениями** (`apps/*`), общий код в `packages/kit`: изоляция
  прототипов и чистая единица для передачи; настройка VKUI не дублируется.
- **Навигация — средствами VKUI**: ключ панели/вью — проп `nav` (не `id`); переходы анимирует
  сам VKUI по смене `activePanel`/`activeView` + `history`.
- **API VKUI 8 сверять по** `node_modules/@vkontakte/vkui/dist/**/*.d.ts`: v8 отличается от
  примеров в интернете (напр. `colorScheme` вместо `appearance`, `nav` вместо `id`).

## Скиллы и инструменты

- Новый прототип — через скилл **`/new-prototype <имя> <таргет>`** (`.claude/skills/new-prototype`);
  скаффолдер **сам регистрирует** прототип в лаунчере (`register.mjs`, идемпотентно) —
  руками остаётся поправить `title`/`description`.
- **`.claude/settings.json`** (шаренный, в git) — allowlist частых безопасных команд
  (Figma MCP read, nvm/npm-скрипты, headless-Chrome литеральным путём, curl своего сайта);
  личные добавки — в `settings.local.json` (не в git).
- **`scripts/doctor.mjs`** — самопроверка окружения; `proto-static` шаг 0 требует шрифты
  до скриншот-сверки (фоллбэк молчаливый).
- Этапы воркфлоу — этапные скиллы (`.claude/skills/`, с 2026-07-02): **`proto-static`**
  (статика + скриншот-сверка), **`proto-animate`** (анимация из Motion-таймлайна),
  **`proto-handoff`** (DoD, деплой, экспорт). Фазы отмечаются чекбоксами в
  `apps/<name>/HANDOFF.md` §«Статус фаз».
- Анимации — скилл **`web-animation-design`** (easing, springs, Framer Motion, reduced-motion).
- **`emil-design-eng`** (Emil Kowalski, MIT, вендорнут) — принципы и конкретные значения motion:
  easing/длительности, «не `ease-in` на UI», «не масштабировать от 0», только `transform/opacity`,
  пружины, асимметричный тайминг, stagger, reduced-motion. Источник motion-вкуса для фазы анимации.
- **`review-animations`** (Emil Kowalski, MIT, вендорнут, `disable-model-invocation`) — строгий
  ревьюер motion-кода (вердикт Block/Approve с `file:line`). **Гейт фазы анимации** в воркфлоу.
  **Переведён на русский и адаптирован под проект (2026-07-02, upstream-синк вручную):** ревьюит
  только кастомный motion (VKUI-дефолты вне скоупа); Block-триггеры — значение не трассируется к
  Figma Motion/спеке/HANDOFF.md, игнор тумблера Motion; длительности — по таблице диапазонов
  (Short 100–200 / Medium 250–400 / Long 450–600 / Extra long 700–1000 мс) и **сетке 50 мс**;
  принятые tradeoff'ы из HANDOFF.md не пере-блокируют; после Approve — чекбокс в «Статус фаз».
- **`agentation`** (npm-пакет, PolyForm Shield, dev-only, **на пробе**) — визуальный фидбек-тулбар:
  клик по элементу рендера → структурный контекст (селектор/путь/computed styles) для агента;
  умеет паузу анимаций для захвата кадра. Подключён в `apps/_template/src/App.tsx` под
  `import.meta.env.DEV` (в прод-сборку не попадает) → во всех новых прототипах. Выпилить =
  удалить импорт + строку рендера + devDependency.
- Figma → код/токены и Code Connect — **Figma MCP-скиллы** (`figma-use`, `figma-code-connect` и др.).
- **`frontend-design`** (официальный Anthropic) вендорнут в `.claude/skills/`, но ценность
  ограничена: эстетику задаёт дизайн-система VKUI.
- **`transitions.dev`** (`github.com/Jakubantalik/transitions.dev`) — каталог готовых CSS-переходов;
  держим **референсом идей**, НЕ ставим как скилл: его `:root`-токены и `t-*`-классы конфликтуют с
  VKUI-токенами и своей дизайн-системой, а переходы экранов уже есть из VKUI.
- **Не ставить** непроверенные community design-скиллы (UI-UX Pro Max, Taste и пр.): навязывают
  generic-эстетику (Tailwind/shadcn) — конфликт с VKUI и риск безопасности.
